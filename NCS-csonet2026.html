Streaming Algorithms for
Monotone k-Submodular Maximization
under Fairness Constraints

Dung T. Pham · Tan D. Tran · Canh V. Pham

ORLab, Phenikaa University, Hanoi, Vietnam

Good afternoon, everyone. Our work studies how to select and label elements in a stream while meeting fairness quotas. I will introduce the problem, explain our two algorithms, and discuss their guarantees and experimental results.

Elements arrive one at a time, and memory is limited. We select some elements and assign each one a single label. The sets on the right collect elements with the same label. The algorithm chooses these labels; they are not fixed groups in the input.
02 · Full problem

Fair streaming maximization

maximize f(S₁, …, Sk)

ℓi ≤ |Si| ≤ ui lower / upper quota for each label group i

∑i |Si| ≤ B total selection budget

Si ∩ Sj = ∅ for distinct labels i and j

Decision variables

Sᵢ: elements assigned label i, for i = 1, …, k.

Objective value

Find a feasible assignment with maximum value f(S₁, …, Sₖ).

The function is monotone and k-submodular: adding a labeled element cannot reduce the value, and marginal gains satisfy diminishing returns.

Assumptions: n ≥ B ≥ 1, 0 ≤ ℓᵢ ≤ uᵢ, and ∑ᵢ ℓᵢ ≤ B ≤ ∑ᵢ uᵢ. Theory assumes exact value-oracle access.

We want to maximize f while meeting three constraints: a lower and upper quota for each label, a total budget B, and at most one label per element. Adding elements cannot reduce the objective, and marginal gains diminish for compatible assignments. Under our assumptions, an optimum can use exactly B elements. The theory assumes exact value oracles.
03 · Challenges

Lower quotas and conflicting labels

A

Budget must leave room for deficits

Early selections can consume the slots that other labels still need.

A partial assignment must remain completable.

B

The same element can have two labels

Algorithm: (e, 1)

Optimum: (e, 2)

The pair-set union is not a valid k-set.

The analysis must compare assignments without creating label conflicts.
There are two main challenges. First, early choices may leave too little budget to meet the remaining lower quotas. Second, our algorithm and an optimum may give different labels to the same element. Simply combining the two assignments could therefore violate the one-label rule.
04 · Key idea

Fair extendability

A partial assignment only needs to admit a fair completion.

|Si| ≤ ui ∀i and ∑i max{|Si|, ℓi} ≤ B

Illustrative example · k = 3 · B = 9 · ℓ = (2, 2, 2) · u = (6, 6, 6)

Element–label pairs + quota matroid characterize extendability for valid k-sets.
Our key idea is fair extendability: a partial assignment must still be possible to complete. For each label, reserve the larger of its current count and its lower quota. The total must fit within B, and no upper quota may be exceeded. Here, counts of four, one, and zero need eight slots; six, one, and zero need ten. With B equal to nine, only the first state is extendable. The quota matroid captures this condition for valid assignments.
05 · Completion

A shared buffer completes the assignment

min{n, 2B}first stream elements retained
  1. Keep the current assignmentPreserve every selected element–label pair.
  2. Fill remaining quota deficitsUse distinct unused elements from the buffer.
  3. Fill the remaining budgetRespect every upper quota and reach size B.
No extra pass · All quotas satisfied · Objective value never decreases
Both algorithms keep the first n elements or the first two B elements, whichever is fewer. This buffer provides enough unused elements to complete the solution. We first meet the remaining lower quotas, then fill the budget within the upper quotas. Completion preserves the selected elements and cannot decrease the objective value.
06 · One pass

OPFSA

Deterministic selection with quota-preserving replacements

  1. Maintain geometric value guessesEach lane stores an archive and a live assignment.
  2. Evaluate a new elementCompute marginal gains against the archive.
  3. Accept a sufficiently valuable pairRemove a minimum-weight quota blocker if needed.
  4. Complete and compareReturn the best completed active lane.

Acceptance rule

ai ≥ (1 + √2)θi + εv/B

ai: gain against the archive
θi: frozen weight of the blocker
v: value guess

Proof intuition

Frozen weights grow along replacement chains, allowing archive costs to be charged to the final live solution.

OPFSA scans the stream once and maintains several value guesses in parallel. Each guess has an archive and a current solution. If insertion is blocked, the algorithm finds a minimum-weight quota blocker. A new pair is accepted only if its gain covers the replacement cost and the extra threshold. The recorded weights stay fixed and grow along replacement chains, which is the key to the analysis.
07 · Multiple passes

MPFSA

Decreasing thresholds with balanced random label choices

  1. Find the singleton scale MA preliminary pass also fills the shared buffer.
  2. Replay the fixed stream orderDecrease τ by the factor 1 − ε after each pass.
  3. Sample a feasible labelAccept when the best extendable gain reaches τ.

M, (1 − ε)M, (1 − ε)²M, …

Why randomize the label?

A small linear program finds a distribution that balances expected gain against loss in a coupled comparison solution.

Value guarantee: in expectation

Quota feasibility: every execution

At most B label-distribution LPs. Oracle counts exclude the separate LP-solving cost.

MPFSA replays the stream in the same order and lowers its threshold after each pass. It considers labels that preserve extendability. When the best gain reaches the threshold, a small linear program provides a balanced distribution for choosing a label. The value guarantee holds in expectation. After completion, all quotas hold in every execution.

Common range: 0 < ε < 3 − 2√2. For k = 3 and ε = 0.1, the MPFSA guarantee is 0.3. Exceeding 1/3 requires ε < 1/15.

OPFSA gives a deterministic one-pass guarantee of about 0.1716 minus epsilon. MPFSA uses more passes but gives a stronger expected guarantee with memory linear in B plus k. For three labels, its guarantee is 0.4 minus epsilon, or 0.3 when epsilon is 0.1. Both algorithms return exactly B elements and meet all quotas.

All methods share the evaluator, seed, and stream order. We use one hundred Monte Carlo worlds for decisions and a separate one thousand for evaluation. Each configuration runs once, so standard errors reflect evaluation sampling, not variation across runs.

Our framework keeps partial assignments possible to complete fairly. OPFSA provides a deterministic one-pass method. MPFSA offers a stronger expected guarantee with multiple passes and low memory. Both meet all quotas and return exactly B elements. Improving the one-pass factor and reducing the number of passes remain open questions. Thank you. I welcome your questions. Q&A reminders: the one-pass bound has not been proved tight. Fairness applies to labels chosen by the algorithm, rather than fixed input groups. The theory assumes exact value oracles; the experiments use Monte Carlo estimates.
