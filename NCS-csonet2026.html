Problem definition

Input stream

A stream of n elements, with k possible labels.

Selection and labeling

Assign each element to one label or leave it unlabeled. Let Sᵢ be the set of elements assigned to label i.

Objective

Find sets S₁, …, Sₖ that maximize f(S₁, …, Sₖ), where f is monotone and k-submodular.

maximize f(S₁, …, Sₖ)

ℓᵢ ≤ |Sᵢ| ≤ uᵢ for all i

∑ᵢ |Sᵢ| ≤ B

Sᵢ ∩ Sⱼ = ∅ for i ≠ j

Our problem is as follows. Given a data stream of \(n\) elements, each element can be assigned to one of \(k\) labels or left unlabeled. Select and label at most \(B\) elements to maximize a monotone \(k\)-submodular objective, while ensuring that the number of elements assigned to each label is within its lower and upper bounds.

Elements arrive one by one. We have limited memory. We choose which elements to keep and give each one a label. The algorithm chooses the labels. They are not fixed input groups.

Monotone k-submodular functions

A function on labeled sets

S = (S₁, …, Sₖ) consists of pairwise disjoint sets. Each element has one label or is unlabeled.

Marginal gain

The extra value from assigning an unused element e to label i:

Δₑ,ᵢf(S) = f(S + eᵢ) − f(S)

Diminishing returns

Adding the same element with the same label gives no more gain in a larger compatible assignment.

Δₑ,ᵢf(S) ≥ Δₑ,ᵢf(T)

For Sⱼ ⊆ Tⱼ for all j, with e ∉ ⋃ⱼ Tⱼ.

Monotonicity

Δₑ,ᵢf(S) ≥ 0

Adding a labeled element never reduces the value.

The function gives a value to the labeled sets. The marginal gain is the extra value from adding one element to one label. For a monotone k-submodular function, this gain cannot be negative. It also has diminishing returns: adding the same element to the same label gives no more gain when the assignment is larger. The larger assignment must keep all existing labels.

Label conflicts

Comparing the algorithm with the optimum

Algorithm: (e, 1)

Optimum: (e, 2)

The two solutions may assign different labels to the same element. Combining them directly may violate the one-label-per-element rule.

There are two challenges. First, choosing too many elements for some labels may leave too little budget for the minimum quotas of other labels. For example, let the budget be six and let each of two labels need at least two elements. If we select five elements for label one and none for label two, only one slot remains. That is not enough for label two. Second, in the analysis, we compare our solution with an optimal solution. They may give different labels to the same element. We cannot simply combine them, because each element can have only one label.
Key idea

Fair extendability

A partial assignment only needs to admit a fair completion.

|Si| ≤ ui ∀i and ∑i max{|Si|, ℓi} ≤ B

Illustrative example · k = 3 · B = 9 · ℓ = (2, 2, 2) · u = (6, 6, 6)

Our main idea is to keep a solution that we can still complete. For each label, we reserve enough space for its minimum quota. The total must fit within B, and no label can exceed its maximum quota. In this example, eight slots fit within nine, but ten slots do not.
Completion

A shared buffer completes the assignment

min{n, 2B}first stream elements retained
  1. Keep the current assignmentPreserve every selected element–label pair.
  2. Fill remaining quota deficitsUse distinct unused elements from the buffer.
  3. Fill the remaining budgetRespect every upper quota and reach size B.
We keep the first n elements or the first two B elements, whichever is fewer. We use this buffer to complete the solution. First, we meet the minimum quotas. Then, we fill the budget without breaking the maximum quotas. Adding these elements cannot reduce the value.
One pass

OPFSA

Deterministic selection with quota-preserving replacements

  1. Maintain geometric value guessesEach lane stores an archive and a live assignment.
  2. Evaluate a new elementCompute marginal gains against the archive.
  3. Accept a sufficiently valuable pairRemove a minimum-weight quota blocker if needed.
  4. Complete and compareReturn the best completed active lane.

Acceptance rule

ai ≥ (1 + √2)θi + εv/B

ai: gain against the archive
θi: frozen weight of the blocker
v: value guess

Proof intuition

Frozen weights grow along replacement chains, allowing archive costs to be charged to the final live solution.

OPFSA reads the stream once. It tries several guesses for the best value. Each guess keeps a record of accepted pairs and a current solution. If a new pair cannot fit, we may remove an old pair. We accept the new pair only if its gain is high enough. The recorded weights stay fixed and help us prove the guarantee.
Multiple passes

MPFSA

Decreasing thresholds with balanced random label choices

  1. Find the singleton scale MA preliminary pass also fills the shared buffer.
  2. Replay the fixed stream orderDecrease τ by the factor 1 − ε after each pass.
  3. Sample a feasible labelAccept when the best extendable gain reaches τ.

M, (1 − ε)M, (1 − ε)²M, …

Why randomize the label?

A small linear program finds a distribution that balances expected gain against loss in a coupled comparison solution.

Value guarantee: in expectation

Quota feasibility: every execution

At most B label-distribution LPs. Oracle counts exclude the separate LP-solving cost.

MPFSA reads the same stream several times. It lowers the threshold after each pass. It only considers labels that leave a solution we can still complete. If the gain is high enough, a small linear program helps it choose a label at random. The value guarantee is an average over its random choices. The final solution meets all quotas every time.

Common range: 0 < ε < 3 − 2√2. For k = 3 and ε = 0.1, the MPFSA guarantee is 0.3. Exceeding 1/3 requires ε < 1/15.

OPFSA uses one pass. Its guarantee is about 0.1716 minus epsilon. MPFSA uses more passes but has a better average guarantee. Its memory is linear in B plus k. With three labels, the guarantee is 0.4 minus epsilon. Both algorithms select exactly B elements and meet all quotas.
