Problem definition

Input stream

A stream of n elements, with k possible labels.

Selection and labeling

Assign each element to one label or leave it unlabeled. Let Sᵢ be the set of elements assigned to label i.

Objective

Find sets S₁, …, Sₖ that maximize f(S₁, …, Sₖ), where f is monotone and k-submodular.

maximize f(S₁, …, Sₖ)

ℓᵢ ≤ |Sᵢ| ≤ uᵢ for all i

∑ᵢ |Sᵢ| ≤ B

Sᵢ ∩ Sⱼ = ∅ for i ≠ j

Our problem is as follows. Given a data stream of \(n\) elements, each element can be assigned to one of \(k\) labels or left unlabeled. Select and label at most \(B\) elements to maximize a monotone \(k\)-submodular objective, while ensuring that the number of elements assigned to each label is within its lower and upper bounds.

The streaming problem

Elements arrive one at a time

Read a stream of n elements using limited memory.

Elements arrive one by one. We have limited memory. We choose which elements to keep and give each one a label. The algorithm chooses the labels. They are not fixed input groups.

Monotone k-submodular functions

A function on labeled sets

S = (S₁, …, Sₖ) consists of pairwise disjoint sets. Each element has one label or is unlabeled.

Marginal gain

The extra value from assigning an unused element e to label i:

Δₑ,ᵢf(S) = f(S + eᵢ) − f(S)

Diminishing returns

Adding the same element with the same label gives no more gain in a larger compatible assignment.

Δₑ,ᵢf(S) ≥ Δₑ,ᵢf(T)

For Sⱼ ⊆ Tⱼ for all j, with e ∉ ⋃ⱼ Tⱼ.

Monotonicity

Δₑ,ᵢf(S) ≥ 0

Adding a labeled element never reduces the value.

Marginal gain is the extra value from assigning an element to a label. For a monotone k-submodular function, it cannot increase as the assignment grows while preserving existing labels. Adding an element never decreases the function value.

Budget

Comparing the algorithm with the optimum

The two solutions may assign different labels to the same element. Combining them directly may violate the one-label-per-element rule.

Our problem has two challenges. First, selecting too many elements for one label can leave insufficient budget for other minimum quotas. With a budget of six and two labels requiring two elements each, selecting five for one leaves only one for the other. Second, our solution and an optimal solution may assign different labels to the same element. We cannot simply combine them because each element can have only one label.

Key idea

A partial assignment only needs to admit a fair completion.

|Si| ≤ ui ∀i and ∑i max{|Si|, ℓi} ≤ B

Illustrative example · k = 3 · B = 9 · ℓ = (2, 2, 2) · u = (6, 6, 6)

Our main idea is to keep a solution that we can still complete. For each label, we reserve enough space for its minimum quota. The total must fit within B, and no label can exceed its maximum quota. In this example, eight slots fit within nine, but ten slots do not.
Algorithm 1: One-Pass Fair Streaming Algorithm (OPFSA)
Input: \text{Stream }V,\ \text{quotas }(\ell_i,u_i)_{i=1}^k,\ \text{budget }B,\ \text{accuracy }\epsilon
Output: \text{A saturated feasible }k\text{-set }\mathbf x\in\mathcal F_B
  1. m\gets0,\ \mathcal B\gets\emptyset,\ \mathcal V\gets\emptyset;
  2. \textbf{foreach }e\textit{ in the stream }\textbf{do}
  3. \textbf{if }|\mathcal B|<2B\textbf{ then}
  4. \mathcal B\gets\mathcal B\cup\{e\};
  5. m\gets\max\bigl(\{m\}\cup\{\Delta_i(e\mid\mathbf0):i\in[k],\ \langle e,i\rangle\text{ is extendable}\}\bigr);
  6. \mathcal V^{\prime}\gets\{(1+\epsilon)^j:j\in\mathbb Z,\ m\le(1+\epsilon)^j\le Bm/\epsilon\};
  7. \text{delete lanes }v\notin\mathcal V^{\prime}\text{ and initialize }(\mathbf a_v,\mathbf s_v)\gets(\mathbf0,\mathbf0)\text{ for }v\in\mathcal V^{\prime}\setminus\mathcal V;
  8. \mathcal V\gets\mathcal V^{\prime};
  9. \textbf{foreach }v\in\mathcal V\textbf{ do}
  10. \textbf{foreach }\textit{quota-nonloop}\text{ label }i\in[k]\textbf{ do}
  11. a_i\gets\Delta_i(e\mid\mathbf a_v),\ \chi_i\gets c_Q(\langle e,i\rangle,\mathbf s_v);
  12. \theta_i\gets0\text{ if }\chi_i=\emptyset,\text{ and }\theta_i\gets w_{\chi_i}\text{ otherwise};
  13. J_v\gets\{i:a_i\ge c_\star\theta_i+\epsilon v/B\};
  14. \textbf{if }J_v\ne\emptyset\textbf{ then}
  15. i^\star\gets\arg\max_{i\in J_v}a_i,\ z\gets\langle e,i^\star\rangle;
  16. \mathbf a_v\gets\mathbf a_v+z,\ w_z\gets a_{i^\star};
  17. \mathbf s_v\gets\mathbf s_v-\chi_{i^\star}+z;
  18. \textbf{if }m=0\textbf{ then}
  19. \textbf{return }\operatorname{Complete}(\mathbf0,\mathcal B);
  20. \mathbf x_v\gets\operatorname{Complete}(\mathbf s_v,\mathcal B)\text{ for every active lane }v;
  21. \textbf{return }\arg\max_v g(\mathbf x_v);
  1. Maintain geometric value guessesEach guess stores an archive and a current solution.
  2. Evaluate each new elementCompute marginal gains against the archive.
  3. Accept a pair with sufficient gainIf needed, remove the minimum-weight quota blocker.
  4. Complete and compareReturn the best completed solution.

Acceptance rule

ai ≥ (1 + √2)θi + εv/B

ai: marginal gain against the archive
θi: fixed weight of the removed pair
v: value guess

OPFSA reads the stream once. It tries several guesses for the best value. Each guess keeps a record of accepted pairs and a current solution. If a new pair cannot fit, we may remove an old pair. We accept the new pair only if its gain is high enough. The recorded weights stay fixed and help us prove the guarantee.
Algorithm 2: Multi-Pass Fair Streaming Algorithm (MPFSA)
Input: \text{Replayable stream }V,\ (\ell_i,u_i)_{i=1}^k,\ B,\ \epsilon
Output: \text{A saturated feasible }k\text{-set }\mathbf x\in\mathcal F_B
  1. M\gets0,\ \mathcal B\gets\emptyset;
  2. \textbf{foreach }e\textit{ in a preliminary pass }\textbf{do}
  3. \textbf{if }|\mathcal B|<2B\textbf{ then}
  4. \mathcal B\gets\mathcal B\cup\{e\};
  5. M\gets\max\bigl(\{M\}\cup\{\Delta_i(e\mid\mathbf0):i\in[k],\ \langle e,i\rangle\text{ is extendable}\}\bigr);
  6. \textbf{if }M=0\textbf{ then}
  7. \textbf{return }\operatorname{Complete}(\mathbf0,\mathcal B);
  8. \mathbf s\gets\mathbf0,\ x\gets1-\epsilon,\ c_k\gets C_k;
  9. \tau\gets M;
  10. \textbf{while }\tau\ge\epsilon M/B\textbf{ do}
  11. \textbf{foreach }e\textit{ in the fixed stream order }\textbf{do}
  12. \textbf{if }e\notin\operatorname{supp}(\mathbf s)\textit{ and }|\mathbf s|<B\textbf{ then}
  13. L(e)\gets\{i:\mathbf s+\langle e,i\rangle\text{ is extendable}\};
  14. \textbf{if }L(e)\ne\emptyset\textbf{ then}
  15. a_i\gets\Delta_i(e\mid\mathbf s)\text{ for }i\in L(e),\ a_{\max}\gets\max_{i\in L(e)}a_i;
  16. \textbf{if }a_{\max}\ge\tau\textbf{ then}
  17. \text{find }p\in\mathcal D(L(e))\text{ with }G=\sum_i p_i a_i,\ a_{\max}\le c_kG,\text{ and}
  18. \quad(1-p_h)(a_{\max}+a_h)\le c_kG\text{ for every }h\in L(e);
  19. \text{sample }I\sim p,\ \mathbf s\gets\mathbf s+\langle e,I\rangle;
  20. \tau\gets x\tau;
  21. \textbf{return }\operatorname{Complete}(\mathbf s,\mathcal B);
  1. Find the singleton scale MA preliminary pass also fills the shared buffer.
  2. Replay the fixed stream orderDecrease τ by the factor 1 − ε after each pass.
  3. Sample a feasible labelAccept when the best extendable gain reaches τ.

M, (1 − ε)M, (1 − ε)²M, …

Why randomize the label?

A small linear program finds a distribution that balances expected gain against loss in a coupled comparison solution.

Value guarantee: in expectation

Quota feasibility: every execution

At most B label-distribution LPs. Oracle counts exclude the separate LP-solving cost.

MPFSA reads the same stream several times. It lowers the threshold after each pass. It only considers labels that leave a solution we can still complete. If the gain is high enough, a small linear program helps it choose a label at random. The value guarantee is an average over its random choices. The final solution meets all quotas every time.

Common range: 0 < ε < 3 − 2√2. For k = 3 and ε = 0.1, the MPFSA guarantee is 0.3. Exceeding 1/3 requires ε < 1/15.

OPFSA uses one pass. Its guarantee is about 0.1716 minus epsilon. MPFSA uses more passes but has a better average guarantee. Its memory is linear in B plus k. With three labels, the guarantee is 0.4 minus epsilon. Both algorithms select exactly B elements and meet all quotas.
